# Сборки для сайта и itch.io

## Где что лежит

- `game/` — сценарий и ресурсы Ren’Py.
- `website/` — исходники страницы игры. Все дальнейшие правки сайта делаем здесь.
- `web-release-template/` — сохранённые доработки веб-оболочки: страница установки, инструкция iPhone, иконки, manifest, обработка сохранений и загрузки. Используются для обоих выпусков.
- `KG-1.0-web/` — результат сборки Ren’Py.
- `tools/package_web.py` — подготовка двух пакетов из готовой веб-сборки.
- `release/site/` — сайт для Vercel с игрой в `play/`.
- `release/itch.zip` — архив для itch.io с установочной страницей в корне.

Исходная папка веб-сборки при упаковке не изменяется. Каталог release пересоздаётся: вручную его не редактировать. Он исключён из Git и сборок Ren’Py.

## Каждый выпуск главы

1. Сохранить правки сценария. В Ren’Py выбрать проект KG и собрать веб-версию (Web → Build). Проверить, куда записан результат. Не ограничиваться упаковкой вчерашней сборки.
2. Проверить актуальность карты предзагрузки и `pwa_catalog.json` после добавления или замены ресурсов. Упаковщик не пересчитывает их и не компилирует сценарий.
3. В терминале из папки проекта выполнить:

```sh
python3 tools/package_web.py
```

Если Ren’Py создал папку с другим номером версии:

```sh
python3 tools/package_web.py --source "/полный/путь/к/KG-новая-версия-web"
```

4. Получить `release/site/` и `release/itch.zip`. В `release/build-info.json` записана контрольная сумма игры. В обоих пакетах игра одинакова.
5. Проверить новую версию на тестовом HTTPS-адресе, затем публиковать.

При изменении самой веб-оболочки править `web-release-template/`, а не только готовую сборку. После обновления SDK Ren’Py проверить совместимость шаблонных `index.html`, `renpy-pre.js`, `service-worker.js` с новым движком: это доработки текущего SDK, не универсальные файлы для всех версий.

## Vercel

Домен `wrongchoice.marabuba.com` должен принадлежать проекту страницы игры. Настройки корневого `marabuba.com` не менять.

Вариант публикации через существующий GitHub-репозиторий:

- Framework Preset: Other.
- Root Directory: корень репозитория KG (пустое значение).
- Build Command: `python3 tools/package_web.py`.
- Output Directory: `release/site`.
- Install Command: пусто; зависимости npm не нужны.

Для облачной упаковки папка `KG-1.0-web` должна содержать свежую сборку и быть отправлена в Git вместе с website, web-release-template и tools. Если номер папки поменялся, обновить Build Command с аргументом --source. Сначала проверить эти настройки на Preview deployment: наличие Python и лимиты проекта требуют проверки на Vercel. Сам Ren’Py в Vercel не запускается.

Альтернатива — после локальной упаковки отправлять готовую папку через Vercel CLI:

```sh
cd release/site
vercel
```

Выбрать существующий проект игры, проверить Preview. Только после проверки:

```sh
vercel --prod
```

Не публиковать корень KG как готовый статический сайт: там исходники и служебные файлы.

Сценарий: `/` — описание и установка; `/play/index.html?kg-launch=1` — запуск с проверкой хранилища, без повторной инструкции. PWA стартует с игры. Страницы сайта и игры ссылаются на общий manifest.

## itch.io

Глобальный Butler используется кнопкой «Опубликовать на itch.io». Один раз авторизоваться:

```sh
butler login
```

Команда загрузки уже готового архива без повторной сборки (из корня KG):

```sh
butler push release/itch.zip marabuba/kg:html5
```

При первой загрузке Butler создаёт канал html5. После его обработки открыть редактирование marabuba/kg и отметить новый файл «This file will be played in the browser». У прежнего вручную загруженного архива снять этот флаг; сохранить настройки мобильного/полноэкранного запуска и страницу. Последующие загрузки в тот же канал обновляют его автоматически. Успех Butler означает отправку архива: серверная обработка может ещё продолжаться.

Ручная альтернатива: загрузить release/itch.zip через Uploads на странице редактирования игры.

Внутри ZIP index.html лежит прямо в корне. В нём остаётся инструкция установки. Папку release/site на itch.io не загружать.

## Проверка перед публикацией

- Сайт: кнопка «Играть» прокручивает к установке; браузерный запуск открывает игру.
- iPhone: актуальные четыре скриншота; установка, запуск с иконки.
- Android: системная установка при доступном предложении; инструкция, если оно недоступно.
- Сохранить игру, закрыть, открыть, загрузить сохранение.
- Проверить обновление уже установленной PWA и старое сохранение после обновления.
- Проверить предзагрузку, переходы между главами, новые ресурсы.
- На itch.io остаётся отдельная установочная страница.

Первый перенос с корня домена в /play/ требует отдельной проверки старой PWA, её кэша и сохранений. Перед тестом экспортировать важные сохранения. Preview-домен и основной домен имеют разные хранилища: успешный тест на Preview не доказывает миграцию старых сохранений.

## Текущее состояние

Упаковка создаёт оба пакета и проверяет целостность ZIP, совпадение game.zip и неизменность исходной веб-сборки. Она не подтверждает свежесть сценария и не заменяет тест игры. Публикация, установка PWA и обновление на устройствах проверяются отдельно. Оригинал макета в рабочей папке Codex после переноса не является основным исходником.

## Сохранение привязки Vercel CLI

После первой команды `vercel link` в `release/site` упаковщик сохраняет файл `.vercel/project.json` при последующих пересборках. Повторно выбирать проект не нужно. Старые результаты сборки CLI и файлы окружения из `.vercel` не переносятся. При первой сборке без привязки папка `.vercel` не создаётся; выполни `vercel link` один раз. В архив itch.zip привязка сайта не добавляется.

## Кнопки в VS Code

Открыть папку KG и выполнить «Developer: Reload Window» через палитру команд после обновления расширения. Слева в вертикальной панели появится значок коробки «Сборка игры». Внутри — три кнопки сборки и публикации. Из нижней строки кнопки убраны.

- «Собрать»: свежая сборка RenPy и подготовка release/site и release/itch.zip.
- «Опубликовать в Vercel»: отправка готовой папки release/site в проект wrong_choice без сборки.
- «Опубликовать на itch.io»: отправка готового release/itch.zip в marabuba/kg:html5 без сборки. Затем itch.io обрабатывает загрузку.

Кнопки показывают этапы работы в уведомлении справа без открытия терминала. Процент не рассчитывается: отображается текущий этап и индикатор работы. Подробный вывод доступен в панели Output → «КГ — сборка и публикация» или по кнопке «Показать журнал» в итоговом уведомлении. Одновременные сборки заблокированы.

Для публикации нужны предварительная авторизация в выбранной площадке и, для Vercel, привязка release/site. Вход выполняется отдельно: vercel login или butler login. Кнопки работают без интерактивного ввода; если авторизация истекла, повторить вход и запустить нужную кнопку.

Исходники расширения: tools/vscode-release-buttons. Задачи также доступны через Terminal → Run Task, с раздельными целями. Для другого SDK задать RENPY_SDK.

После успешной упаковки удаляются release/web-build и release/web-build.zip. При ошибке сборки или упаковки они остаются для диагностики. При ошибке публикации готовые site и itch.zip сохраняются.

Команды из корня KG:

```sh
python3 tools/release_web.py
python3 tools/release_web.py --publish vercel
python3 tools/release_web.py --publish itch
```

Порядок выпуска: один раз «Собрать», затем по очереди публикация в Vercel и на itch.io. Обе площадки получают файлы одной сборки. Публикация не включает изменения исходников, внесённые после сборки: для них снова нажать «Собрать». При отсутствии готовых файлов публикация останавливается.
